0.5.1 新增验证：

- 只切换项目窗口的 IPC 消息只发送给正确窗口，不调用会话导航，不标读。
- 本机旧通知路径恢复，SSH／容器 authority 保留，多根工作区文件保留；旧远端连接可从 VS Code 最近项目恢复，歧义选择取消时不打开。
- 目标项目关闭或断连后，项目 URI 随通知持久保存；父项目窗口不会接收已关闭子项目的任务跳转。
- URI 校验拒绝命令、网页、查询参数及非法地址；隐私暂停取消正在解析的打开请求。
- 协议 v7 优先迁移 v6，兼容更早缓存，继续受原认证与权限检查保护。
- 真实隔离 VS Code 中，“打开项目窗口”聚焦现有项目；模拟目标断连后重新通过 VS Code 打开已有的同一项目，未读与会话标签保持原状。SSH／容器只验证地址恢复和路由逻辑，未连接真实远端。
- 宿主标题闪动测试等待当前提醒的显示文本更新后再比较帧，避免把上一状态的异步显示误当作当前帧。

0.5.0 功能验证：

- 项目按完整目录和来源分组，Windows 路径大小写规范化，同一轮多条事件合并为一个任务。
- 状态从运行、同步等待、异步等待到恢复与完成；缺少开始记录时标注部分用量。
- 按轮次累计增量，不重复计数；多模型与服务档位分别计价，缓存命中／写入和推理输出不重复收费。
- 自定义单价能刷新已有任务，未知单价与无用量不显示虚假的零费用。
- 用量更新不播放提醒、不增加未读；已读不改变运行状态；清空已读保留活跃任务用量。
- 协议 v6 优先迁移 v5 历史，旧数据与新状态文件继续受原认证及权限检查保护。
- 真实隔离 VS Code 采集器驱动状态与用量更新；真实编辑器跳转、合并任务标读及删除通过。测试中不运行真实模型、不产生 API 费用。

新增的 PowerShell 回归测试先在空 PATH 环境确认按命令名启动会报 ENOENT，再验证修复后的通知与任务栏辅助进程能真实启动并返回确认。回归测试关闭弹窗和声音，不干扰测试桌面。

实际安装版本也在空 PATH 环境下接受了 Windows 弹窗及声音请求，并通过共享通知后台发送合成测试通知；辅助进程使用系统 PowerShell 路径。接口接受请求不证明人眼看见弹窗或扬声器实际发声。

真实宿主测试使用隔离用户数据和合成 Codex 会话，不恢复实际用户聊天。SSH、容器、WSL 以及实际用户会话跳转后的后端恢复未在此次验证范围内。

修复内容：

1. `ui/lib/broker.js` 与 `ui/lib/window-attention-native.js` 复用既有系统 PowerShell 路径函数。
2. `tests/native-powershell.test.js` 覆盖缺少 PATH 的真实启动场景。
3. `tests/broker-core.js` 使用当前时间戳，避免固定时间戳被保留策略过滤。
4. `tests/ipc-security.test.js` 读取拒绝响应并释放测试连接，避免测试挂起。
5. 增加安装、设置备份和设置修改辅助程序。

公开仓库只包含按清单审查的源码和说明。真实会话、运行时凭据、用户设置、测试缓存和本机日志不包含在仓库中。

Windows 托管 CI 通常以提升权限运行，新文件的默认所有者可能是 Administrators。CI 测试启动脚本仅调整本测试进程令牌的默认文件所有者，使新建合成数据与当前用户 SID 一致；插件运行时的所有权、ACL 和通信认证检查保持不变。
